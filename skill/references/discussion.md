# 怎样问出值得讨论的问题

讨论延续刚刚展示的机制或证据。听众应能知道问题从哪里来、什么观察能推进答案。不是每页都需要一个问题，也不把研究组讨论自动变成事实测验。

## 三种用途

| 用途 | 在什么时候问 | 期待什么 |
|---|---|---|
| 理解检查 | 一个关键对象或机制刚讲清 | 听众准确区分输入、操作、输出；可有短答案 |
| 证据解释 | 一项结果刚展示 | 听众说出支持范围、另一种解释或不能推出的结论 |
| 研究讨论 | 有明确缺口，且已给足共同背景 | 提出可比较的设计、反例或能区分解释的实验 |

用户明确要抽牌、考试或有标准答案时才转成题库；不要把该活动当作所有研究报告的默认结尾。

## 出题步骤

1. 指定锚点：哪一步机制、哪张图、哪一项未测条件？
2. 找一个真正的选择或不确定性：比较对象是否公平、局部收益是否有另一原因、换条件会发生什么？
3. 把它压成一个能口头听懂的问题。复杂术语在前文定义，题面不塞三问。
4. 私下记录最低回答、值得追问的分歧和推进讨论所需证据。开放题可以没有标准答案，但不能没有讨论方向。
5. 检查听众是否已经见过回答所需的材料；未见过则补背景或换问题。

## 可复用问题形式

方括号替换成实际对象。句子应按新材料重写，避免机械套词。

| 目标 | 问法模板 | 何时有用 |
|---|---|---|
| 区分对象 | “这里检索的是【query/trace/其他对象】中的哪一个？” | 容易混淆存储内容与检索键 |
| 检查适用条件 | “【条件】变了，这条经验还适用吗？” | 已展示具体策略及其边界 |
| 揭示指标差别 | “这张图说明【候选里有正确答案】，还是【最终选对了】？” | 同一系统有多种评估协议 |
| 追问替代解释 | “这个提升也可能来自【替代因素】吗？” | 确有未隔离因素，不能制造虚假争议 |
| 设计区分实验 | “怎样区分【解释A】和【解释B】？” | 两个解释都与现有证据相容 |
| 选择设计 | “要处理【已展示的失败】，你会先改哪一步？” | 已讲明系统，可比较代价与收益 |
| 扩展范围 | “换到【新条件】，最先失效的可能是哪一项假设？” | 已经进入明确的general-topic模式 |

## 原稿中的具体改进示例

**失败经验图（28）：**

- 低价值问法：“失败经验重要吗？”答案太容易停在“Yes”。
- 更好的理解题：“为什么同样加入失败，两个方法的变化方向会不同？”
- 研究题：“怎样区分失败记录本身的价值与提炼方式的价值？”
- 主持人备忘：当前图未隔离所有机制；可比较保存原轨迹与提炼策略，并保持任务和预算可比。不要把建议对照说成论文已有实验。

**Judge标签图（29）：**

- 问题：“只改变成败标签准确率，能判断提炼器是不是主要瓶颈吗？”
- 追问：“还需要固定什么、改变什么？”
- 主持人备忘：标签质量与提炼能力要分开。听众提出对照后再追问数据与评估，避免题面一次塞满全部设计。

**检索数量图（30）：**

- 问题：“多取几条为什么没有继续提高？”
- 若听众直接回答“噪声”，追问：“怎样验证是噪声，而不是长度、冲突或适用条件？”
- 主持人备忘：原因是假设。该图改变取用条数，不是库总容量；不从这张图推出普遍最优数量。

**表示地图（38）：**

- “如果把文本记忆换成向量状态，哪一种操作最难验证？”
- 主持人备忘：先让大家在插入、检索、维护、选择、迁移、评估中选一个，再谈可观察的失败；避免“神经表示能否统一解决记忆”这种范围过大的题面。

**本地规则（39）：**

- 先给一个短例：同一网站的退货规则从30天改为14天。
- 再问：“旧经验还在时，agent怎样知道该更新？”
- 主持人备忘：这是教学例子，不是原报告实测；可从发现变更、有效时间和证据来源推进。不要把答案预埋成唯一算法。

## 每个讨论问题的主持卡

```text
可见题面：一句口语问题
锚点：页码/图表/机制
意图：理解 / 解释证据 / 比较设计
最低有效回答：怎样算进入了问题
分歧：哪些不同答案都可能合理
一条追问：把直觉变成证据或设计
收束：哪些已知，哪些仍需测试
```

正式画面通常只放题面，卡片进备注。中途问题可短暂停顿；结尾选择最有支撑的一两个方向深入，不用凑固定数量。

## 问题质量检查

- 问题能指回刚讲过的具体内容。
- 一次只问一个焦点，口头听懂，无需重新读长段落。
- 没有把未证明的原因藏进前提。
- 允许证据支持的不同答案，或明确是理解检查。
- 即使暂时没有答案，也知道下一项观察或对照是什么。
- 如果删掉论文名题目仍适用于所有AI报告，通常还不够具体。
